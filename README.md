Порівняння алгоритмів сортування
Мета
Порівняти швидкість сортування вставками, сортування злиттям і вбудованого сортування Python (sorted, Timsort).
Як проводилося тестування
Використано Python 3.14 та модуль timeit. Кожен алгоритм виконувався 10 разів. У таблицях наведено середній час одного сортування в секундах.
Перевірено випадкові списки з 1000, 2000 і 4000 елементів, а також відсортований і зворотно відсортований списки з 4000 елементів.
Випадкові числа створювалися в діапазоні від 0 до 10000 з використанням random.seed(42) перед кожним набором. Генерація даних і перевірка правильності не входили у вимірювання часу. Усі алгоритми отримували однакові дані та повертали новий список.

Аналіз
Сортування вставками має складність O(n²) на випадкових даних. При подвоєнні розміру списку час зріс приблизно у 3.97 та 4.32 раза, тобто близько до очікуваних чотирьох разів. На відсортованому списку зсуви не потрібні, тому алгоритм працює значно швидше — це найкращий випадок O(n). Зворотний порядок виявився найповільнішим.
Сортування злиттям має складність O(n log n). При збільшенні списку з 1000 до 4000 елементів час зріс приблизно у 4.86 раза, тоді як для n log n очікується близько 4.80 раза. Початковий порядок даних впливає на нього менше, ніж на вставки.
Timsort був найшвидшим у всіх тестах. На випадкових даних його складність — O(n log n): подвоєння розміру збільшило час приблизно у 2.41 та 2.19 раза. На впорядкованих списках він працював ще швидше, оскільки використовує вже відсортовані ділянки та розпізнає спадні послідовності. Його найкращий випадок — O(n).
Timsort поєднує вставки для коротких ділянок і злиття для їх об’єднання. Це допомагає ефективно обробляти різні дані. Також вбудоване сортування CPython реалізоване на C, тому його перевага пов’язана не лише з алгоритмом, а й із реалізацією.
Висновки
- Результати узгоджуються з теоретичними оцінками складності, хоча вимірювання часу не є математичним доказом.
- Вставки швидкі на вже відсортованих списках, але повільні на великих випадкових списках.
- Злиття краще підходить для великих випадкових списків, ніж вставки.
- Timsort показав найкращий час у всіх випадках. Для 4000 випадкових елементів він був приблизно у 765 разів швидшим за вставки та у 21 раз швидшим за злиття.
- Для практичних задач доцільно використовувати sorted() для створення нового списку або list.sort() для сортування наявного.
Час виконання може відрізнятися залежно від комп’ютера та навантаження системи.
